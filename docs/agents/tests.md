# Tests

Part of the project guide. The short index and the must-not-break rules are in [AGENTS.md](../../AGENTS.md).

## Tests
- The vitest suite lives in `tests/` and covers the destructive/critical logic: deploy-path computation (`getDeployRelativePath`, incl. flat/nested REDmod and `..` stripping), `detectModType` (real disk fixtures), the capture sweep (`captureOwnerFolder`/`sweepOrphanCaptures` - proving deletion can never leave a deleted mod's private slot), the FOMOD parser (incl. malformed XML), the renderer conflict recompute (`modConflictState.ts` - unique-resource counts, redundant, pairwise expansion, load-order direction), `parseNxmUrl` + the Nexus update-lineage helpers, the installer naming helpers (`sanitizeFolderName`/`uniqueFolderName`/`uniqueDisplayName`/`parseMetaIniNexusInfo`/`shouldPreserveArchiveRootFolder`), `parseRed4Archive` hardened against corrupt/truncated/hostile archives, `nexusDownloadRegistry` (upsert/lookup/dead-record prune), and `buildEnabledModLinks` (ordered VFS mounts, load-ordered virtual archive names, dedup).
- Main-process modules import `electron` at module load; `vitest.config.ts` aliases it to the stub in `tests/stubs/electron.ts` (plus the `@shared` alias). The suite runs outside Electron - keep units under test pure (no electron API calls at function-call time).
- DOM-dependent suites (fomodParser) opt into happy-dom with a `// @vitest-environment happy-dom` pragma; everything else runs in node.
- Tests are typechecked by `tests/tsconfig.json` (`npx tsc --noEmit -p tests/tsconfig.json`) - living inside `tests/` means the IDE picks it up automatically for test files (node types included). CI (`.github/workflows/test.yml`) runs typecheck + suite on every push/PR with `npm ci --ignore-scripts` (no Electron binary needed).
- When changing deploy-path rules, mod-type detection, capture cleanup, conflict math, FOMOD parsing, or update-lineage logic, update/extend the corresponding test file in the same task.
- **E2E smoke test**: `npm run test:e2e` builds `out/` (`electron-vite build`) and drives the REAL app via playwright-core's `_electron` (`tests/e2e/smoke.mjs`) inside an **isolated throwaway profile** - `tests/e2e/harness.cjs` redirects `userData`/`sessionData` to a temp dir (`HYPERION_E2E_PROFILE`) and no-ops `setAsDefaultProtocolClient` so the machine's real settings, library, downloads and nxm handler are never touched. Two scenarios: (1) empty profile boots into the welcome screen; (2) seeded profile (fake game dir with `bin/x64/Cyberpunk2077.exe`, two fixture zips sharing an `r6/scripts` path) - installs both from the Downloads screen, asserts the +1/-1 conflict badges, exercises the mod-details Files tree with REAL disk assertions on TEST-ONLY entries (create `smoke_e2e_folder` inside `r6`, rename it, delete it through the confirm dialog - each step checked on disk; the mod's own files are never touched, and the tree must keep the mod's files through the watcher's slim rescan), asserts the action toast renders ABOVE the open modal (elementFromPoint probe), plus search filtering, that disabling one mod clears the pair, and delete-with-confirm removes the folder from disk. Screenshots land in `tests/e2e/artifacts/` (gitignored); any renderer `pageerror` fails the run. Local-only - not in CI (needs the Electron binary + display). Driver gotchas already handled in the script: clear `ELECTRON_RUN_AS_NODE` before launching; the splash is a separate data:-URL window (wait for the `index.html` window); `getByLabel` matches substrings ("Install archive" ⊂ "Reinstall archive" - use `exact: true`); park the mouse off the sidebar after nav clicks (it expands on hover and intercepts row clicks); HeroUI switches need `click({ force: true })` (visual control overlays the hidden input). The header version chip shows Electron's version under the harness (package.json identity isn't loaded) - cosmetic, test-only. Run it before cutting a release.
