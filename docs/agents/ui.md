# UI Implementation

Part of the project guide. The short index and the must-not-break rules are in [AGENTS.md](../../AGENTS.md).

## Component library
- UI is built with the **HeroUI v3** component library (`@heroui/react` + `@heroui/styles`) on **React 19 + Tailwind v4** (via `@tailwindcss/vite`). HeroUI needs no provider - its components read theme CSS variables (`--accent`, `--surface`, `--overlay`, `--foreground`, …) straight from `<html class="dark">`, which the Hyperion accent system drives. There is **no MUI/@emotion/framer-motion** - those were removed in the HeroUI migration. Primary font is **Inter**. Shared wrappers live in `src/renderer/features/ui/HyperionPrimitives.tsx` (`HyperionButton`/`HyperionSwitch`/`HyperionBadge`/`HyperionSearchField`/`HyperionPanel`, plus the `HyperionModal`/`HyperionModalHeader` dialog shell); the shared tab patterns (`UnderlineTabs`/`SegmentedTabs`) and `SettingCard` live in `src/renderer/features/ui/uiKit.tsx`, `Tooltip.tsx` wraps the real HeroUI Tooltip, and dialogs use HeroUI `CloseButton`. Toasts are real HeroUI Toasts: the store's `addToast(message, severity, duration)` (signature unchanged at every call site) pushes into the global HeroUI `ToastQueue` in `src/renderer/features/ui/toastQueue.ts`, rendered by `ToastContainer.tsx` via `<ToastProvider placement="bottom end">`; severity→variant map lives there (info follows the accent). Project tokens live in `src/renderer/styles/globals.css`.

## UI Rules
- Preserve the HeroUI-based Hyperion look: near-black flat surfaces, borderless rounded panels, one user-selected accent color as the only signal color, and **no drop shadows anywhere** - modals, context menus, popovers, toasts, tooltips and floating bars separate from the page via their border + the dimmed backdrop, never via a cast shadow (the shared `Tooltip` pins `shadow-none` to override HeroUI's default). Inset ring "shadows" used as borders/focus indicators are fine; do not reintroduce `shadow-[0_...rgba(0,0,0,...)]` classes.
- Do not introduce purple-heavy palettes, glassmorphism, neon Tron motifs, scanlines, or random gradients.
- Routine buttons, badges, status readouts, progress icons, toggles, and row actions should use borderless filled/tinted surfaces instead of colored outline boxes. Keep borders for containers, tables, separators, and structural grouping.
- Settings sections use the shared `SettingCard` as single-column HeroUI cards: sentence-case title/description (no decorative icon tile) in the header with the compact control on the right, richer content below aligned under the title, cards stacked with vertical gaps on the darker page background.
- All tab strips share one pattern: `UnderlineTabs` for primary sections (Settings, App Logs, Mod Details) and `SegmentedTabs` for sub-levels inside a section (see the Tabs section below).
- About-page outbound links should not look like plain text. Use filled secondary button surfaces with subtle inset boundaries and visible hover/focus states for GitHub, Releases, issue reporting, usvfs, MO2, and REDmodding.
- Managed Mods status filtering is a compact readout (`All N | On N | Off N`) under the title, not a dropdown. Keep it as the shared segmented pill control (active segment lifted on `--surface-secondary`), and show a small `Viewing enabled` / `Viewing disabled` clearable notice in the toolbar whenever the filter is not `All`.
- Conflict badges on mod rows are `+N` green, `-N` red, and a warning-yellow `!` for redundant (semantic warning color, not the accent). Their tooltip is a compact JSX tooltip with color-separated rows; keep the full combined explanation in `aria-label` for accessibility.
- Sidebar navigation is intentionally compact when collapsed and expands on hover.
- Current sidebar nav items are Mods, Downloads, and Settings, plus the Launch Game CTA. Purely informational chips (account tier, status readouts) are HeroUI Chips and must never look like buttons; Premium stays gold while Free follows the accent color.
- The terminal badge above navigation is decorative reference UI, hidden until sidebar hover. It is not a functional terminal.
- The terminal icon in the header opens App Logs.

## UI Theming

> [!IMPORTANT]
> **Every new user-facing color must be token-aware.** When writing renderer UI, never hardcode a literal hex/rgba value for a background, border, or accent color. Reference the CSS custom property instead (`bg-[var(--surface)]`, `text-[var(--accent)]`, `border-[rgb(var(--accent-rgb)/0.3)]` for arbitrary accent opacities). A hardcoded identity-color literal is a bug the same way a hardcoded English string is - it silently breaks when the user picks a different accent color. The only colors that should stay hardcoded are semantic/status colors (success/error/warning/info), the Nexus **Premium gold**, and the per-mod-type colors - those carry fixed meaning and never follow the accent.

- Hyperion has **two visual axes**: a **light/dark/system mode** (header segmented toggle, `AppSettings.uiMode`, default `'system'` resolved via `prefers-color-scheme` with a live listener) and a **user-selectable accent color** (Settings > General "Color"). There is **no theme selector, no Themes folder, and no community-theme JSON support** - that system was removed. Do not reintroduce a theme list/IPC.
- **Base tokens**: `src/shared/theme/palettes/dark.json` holds the dark factory values (`BASE_THEME_TOKENS` in `src/renderer/theme/themes.ts`); `light.json` (`LIGHT_THEME_TOKENS`) holds the light-mode overrides for Hyperion's identity tokens - HeroUI's own component tokens flip automatically when `AppThemeProvider` toggles the `dark` class on `<html>`. The provider applies dark tokens, then the light overlay when resolved light, then the accent overlay **last** so the chosen color always wins. `useTheme()` exposes `{ mode, resolvedMode, setMode, accentId, setAccentId, accents }`. In HeroUI light the page canvas (`--bg-canvas`) is light gray and cards are white - not the inverse.
- **CSS token architecture** (`src/renderer/styles/globals.css`): `:root` declares every identity token with the dark values as the compiled-in default/fallback - `--bg-base`, `--bg-base-deep` (darker shade kept for brand accents/legacy fills; the shell header is transparent over the canvas and the sidebar is a full-height floating rail on the HyperionPanel card language (`--overlay` + `--border`) with the brand mark at its top - neither uses base-deep or hairline divider borders), `--bg-surface`, `--bg-elevated`, `--bg-subtle`, `--bg-overlay`, `--border-default/subtle/strong/accent`, `--text-primary`, `--text-primary-alt` (a second, slightly different off-white kept as its own token - never merge the two), `--text-secondary/muted/disabled/support/accent`, `--accent`, `--accent-hover`, `--accent-dim`, and `--accent-rgb` (a **space-separated** companion to `--accent` - see below). `--status-*` and `--type-*` tokens are constant and never recolored by the accent.
- **The `rgb(var(--token-rgb)/opacity)` convention**: components frequently need the accent color at an arbitrary opacity (`/0.08`, `/0.3`, etc.). The fix is a companion `--accent-rgb: 0 111 238` variable and Tailwind arbitrary `rgb()`-with-slash-opacity syntax: `bg-[rgb(var(--accent-rgb)/0.08)]`. **The channels MUST be space-separated (`0 111 238`), NOT comma-separated** - `rgb(0, 111, 238/0.08)` is invalid CSS and computes to fully transparent, silently rendering every `rgb(var(--accent-rgb)/X)` element with no fill (this bit the mod-row hover/selection). This applies to `--accent-rgb`, `--accent-cyber-blue-rgb`, and any future `*-rgb` channel token, in `globals.css`, `accents.ts` (`ACCENT_PRESETS[].rgb` + `accentTokens`), and `dark.json`. If you ever need the legacy `rgba(var(--x), a)` comma form, the token must be comma-separated instead - do not mix. Do not reintroduce hardcoded `rgba(...)` accent literals; they opt that element out of the accent system.
- **Punctual secondary accent**: `--accent-cyber-blue` plus its `--accent-cyber-blue-rgb` companion is reserved for a small, deliberately limited set of "punctual" UI moments (separator-membership indicators, conflict/organize actions, archive-extraction progress) - it must **not** become a second dominant color competing with `--accent`.
- **`.hyperion-bg`** is a flat near-black backdrop (`#070709`, no gradients/texture - removed in the HeroUI redesign); `.hyperion-scrollbar` thumb colors stay token-driven (`--scrollbar-thumb(-hover)`). Never reintroduce decorative glow layers inline.
- **HeroUI**: HeroUI v3 components read their own semantic tokens (`--surface`, `--surface-secondary`, `--overlay`, `--background`, `--foreground`, `--default`, `--border`, plus `--accent`/`--accent-foreground`) from `<html class="dark">` - the dark values ship in `@heroui/styles` and Hyperion overrides only the accent tokens via the accent overlay. Because everything resolves from live CSS variables, HeroUI components re-skin instantly when the accent changes, with no provider and no second theme object. Surface hierarchy convention: page/modal shells on `--background` (or the flat `.hyperion-bg`), cards/panels on `--surface`, nested rows/inputs/secondary buttons on `--surface-secondary` - all **borderless** (no white inset rings); hover feedback comes from a background shift (`color-mix(in srgb, var(--surface-secondary), white 7%)`), not from borders.
- **Chips/badges are the real HeroUI `Chip`** via the `HyperionBadge` wrapper in `HyperionPrimitives.tsx` (soft variant; tones accent/neutral/success/warning/danger). Prefer it over hand-rolled `<span>` chips.

## Icons
- All icons are **Lucide** (`lucide-react`), rendered through one central component: `src/renderer/features/ui/Icon.tsx`. `<Icon name="folder_open" className="text-[18px] text-[var(--accent)]" />` maps a legacy name string to a Lucide component and renders it at `1em` (via `style width/height: 1em`), so the existing `text-[Npx]` sizing and `text-[color]`/`currentColor` classes control size and color exactly like the old font icons did - a drop-in. The **Material Symbols font was removed** (no `<link>` in `index.html`, no `.material-symbols-outlined` CSS). Do NOT reintroduce Material Symbols or any other icon set. To use an icon, either pass its name to a primitive `icon="..."` prop (HyperionButton/HyperionIconButton/etc.) or render `<Icon name="..." />`; if a name is not in the `ICONS` map yet, add the mapping there (name string -> Lucide component) rather than inlining an SVG - an unmapped name silently renders the fallback `Square`, which reads as a meaningless empty box in the UI (this bit the sidebar `inventory_2`).

## Tabs (one shared pattern)
- **Primary sections use `UnderlineTabs`** (`src/renderer/features/ui/uiKit.tsx`): HeroUI-docs-style rail - icon + sentence-case label + optional count chip, muted inactive, active tab in primary text with a rounded accent underline sitting on the divider line. Used by Settings, App Logs, and (via the matching `TabButton` in `DetailPanelParts.tsx`) the mod-details modal.
- **Sub-level tabs inside an active section use `SegmentedTabs`** (same file): a compact pill group on `--surface` with the active segment lifted on `--surface-secondary`. Used by the mod-details Conflicts tab (`Paths` / `.archive`) so two underline rails never stack.
- Do not hand-roll a third tab style; pick one of these two by hierarchy level.

## Accent Color (Settings > General "Color")
- The **accent color is the single user-facing visual customization**: it recolors every button, switch, tab and highlight over the fixed dark base. Default is the HeroUI blue (`#006FEE`, white foreground).
- Presets live in `src/shared/theme/accents.ts` (re-exported by `src/renderer/theme/accents.ts`, which adds the CSS-token mapping; the main-process splash reads the same presets) (`ACCENT_PRESETS`: blue, cyan, green, yellow, orange, red, pink, purple - each `{ id, label, accent, foreground, hover, rgb }`). `accentTokens(preset)` maps a preset to the CSS custom properties it overrides (`--accent`, `--accent-foreground`, `--accent-hover`, `--accent-dim`, `--accent-rgb`, `--text-accent`, `--border-accent`, `--focus-ring`). `AppThemeProvider` applies these **last**, over the base tokens, so a single choice recolors HeroUI + Hyperion legacy UI live - including the setup/welcome screen when it reappears.
- Persisted as `AppSettings.accentColor` (`src/shared/types.ts`; defaulted to `'blue'` in `normalizeSettings`, `settings.ts`). The selector UI is `src/renderer/features/ui/AccentSelect.tsx` (swatch row), mounted in Settings > General after the Language card. Status colors, the Nexus Premium gold, and per-mod-type colors are never affected; the sidebar **Free** tier chip follows the accent while **Premium** stays gold.
